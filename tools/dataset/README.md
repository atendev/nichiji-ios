# Dataset generator

Builds the committed `Dataset/` bundle from KANJIDIC2, JMdict, KanjiVG and the pinned N-level lists. Standard-library Python 3.10 or newer, no dependencies. Not part of any app target.

- `make dataset-fetch` downloads the inputs into untracked `.cache/` and rewrites `sources.lock.json` (URL, SHA-256, upstream version). KanjiVG r20260714 and the Waller and OpenJLPT files at commit `0d1d341` are hash-enforced. The EDRDG files roll, so their hash and version are recorded but not enforced.
- `make dataset` runs offline from `.cache/` and is deterministic. It fails if a cached file does not match `sources.lock.json`, a KanjiVG stroke count differs from KANJIDIC2 outside `strokecount-allowlist.json`, or the output passes 8 MB (Shared) or 24 MB (Shared plus AppOnly). A KanjiVG file is required only for Jōyō kanji.
- `make dataset-test` runs the unit tests on small inline fixtures.

Output: `Dataset/Shared/` (`kanji-index.json`, `kanji/<hex>.json`, `DATA-SOURCES.md`) goes to both targets, `Dataset/AppOnly/` (`stroke-order/<hex>.svg`, `words.json`, `kanji-search.json`) to the app only. SVGs keep only the ordered stroke paths; the licence and attribution live in `DATA-SOURCES.md`.

Refresh for every App Store release: run `make dataset-fetch`, `make dataset`, review the diff, and commit. Ship a data-only patch if the EDRDG snapshot is older than 6 months.

Selection rules: 6,407 kanji. Every KANJIDIC2 kanji with a Jōyō grade (2,136), grade 9 or 10 (806 Jinmeiyō, 247 of them Waller N1) or a JIS X 0208 code point (3,465 more, the Hyōgai) is in, and so is any Waller-listed kanji. Every record and index entry carries `classification` (`joyo`, `jinmeiyo` or `hyogai`), which both level ladders derive from; `joyoGrade` stays Jōyō-only. N-levels come from Waller, with the OpenJLPT supplement for Jōyō kanji only, so a Jinmeiyō or Hyōgai kanji outside Waller has no `jlptLevel`. List order is the KANJIDIC2 frequency rank (unranked last), then the number of JMdict common words that use the kanji (more first), then stroke count, then code point. The 32 Jinmeiyō kanji KanjiVG lacks get no stroke SVG. Up to 3 JMdict examples per kanji, ranked by priority tier, then same-or-easier Waller vocabulary level, then `nf` band, then sequence number. Headwords with digits, Latin letters or `sK/iK/oK/rK` forms are dropped, and every kanji in a word must be in the bundle. `words.json` holds the same words restricted to the common tier (`news1`, `ichi1`, `spec1`, `gai1`).

Search files: each `words.json` record carries `rank`, lower is more common: the lowest JMdict `nf` band (1 to 48), else 50 plus the number of the four common tags the word lacks. `kanji-search.json` lists every kanji's full meanings and onyomi and kunyomi (kana and romaji, markers kept) for the in-app search index. The 2,136 + 806 + 3,465 kanji give a 5.1 MiB Shared set and a 16.8 MiB app set, within the 8 MiB and 24 MiB budgets, with 19,025 common words, 6,375 stroke SVGs and 93 more KanjiVG stroke-count mismatches in `strokecount-allowlist.json` (102 in all).
